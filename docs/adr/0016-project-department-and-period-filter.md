# 0016. 案件に部署を持たせ、 一覧を部署と期間で絞る

- **Status**: Accepted
- **Date**: 2026-11-10
- **Deciders**: @tommykey0925

## Context

案件 (Project) は作るほど一覧に溜まり、 終わった案件と動いている案件の区別がつかない。 一覧で絞れるのは
案件名と使用技術だけで、 部署でも日付でも絞れない。

案件には必ず、 受注した部署か、 受注を見込んでいる部署がある。 しかし今の Project は
`{ id, name, color, description?, tags?, links? }` だけで、 部署を表す属性がない
(ADR 0010 は状態・顧客・責任者を対象外として後回しにした)。

日付については、 案件の期間を案件自身に持たせるかが論点になる。 このアプリでは期間は割り当て (Assignment) が
半開区間 `[startDate, endDateExclusive)` で持つ (ADR 0004 / ADR 0012)。

既製の要員計画ツールの扱いを調べた:

| 項目 | 既製品 |
|---|---|
| 案件の部署 | Runn は案件に主チーム (Primary Team) を 1 つ持たせる。 Float は担当者と顧客で絞る。 Resource Guru は独自欄で部署を作るよう勧める |
| 案件の日付 | Runn は案件に開始日の欄を持たず、 最初と最後の割り当てなどから決める |
| 部署の削除 | Float は部署を消すと所属を空にする (サードパーティの API 文書による。 公式の記述は未確認) |

## Decision

1. **Project に `departmentId?` を足す。** Resource と同じ規約にする: 高々 1 つ、 木の任意のノード、
   未所属は属性なし (REMOVE)、 保存時に部署の存在は確認しない。 名前ではなく ID を持つので、
   部署の名前を変えても案件側の書き換えはいらない。
2. **案件に期間を持たせない。** 一覧の期間の絞り込みは「選んだ期間と 1 日でも重なる割り当てを
   1 件以上持つ案件」を出す。 選択肢は今日 / 今月 / 今年 / すべて、 初期値は今月。 割り当てが 0 件の案件は
   「すべて」でだけ出る。
3. **部署の絞り込みは子孫を含む。** 初期値はログインユーザーの部署 (ADR 0015 と同じ)。
4. **部署を削除したら、 その部署に直接属する案件は未所属にする。** 子部署とメンバーは ADR 0013 のとおり
   親へ移す。 削除の確認ダイアログで、 紐づく案件の件数と「案件は消えず、 あとで別の部署に紐づけられる」ことを伝える。
5. **既存の案件は移行スクリプトで部署を埋める。** 割り当てられたメンバーの今の部署を 1 割り当て 1 票で数え、
   最多の部署を入れる。 同数・割り当て 0 件・全員未所属の案件は入れずに一覧に出し、 人が決める。

### 部署の削除でメンバーと案件の扱いが違う理由

メンバーは組織のどこかに属する人で、 部署がなくなれば上の部署に属するのが自然 (ADR 0013)。
案件の部署は「どの部署が受注したか」という事実で、 部署を消しても親の部署が受注したことにはならない。
親へ移すと事実を書き換えてしまうため、 所属を空にする。

## Consequences

### Positive

- 一覧の既定が「自分の部署 × 今月に動いている案件」になり、 溜まった案件が目に入らなくなる
- 期間の事実は割り当てにだけあり、 案件と割り当ての期間が食い違わない
- 絞り込みは手元のデータで行うので、 DynamoDB のアクセスパターンは増えない

### Negative

- 割り当てを入れる前の案件は、 期間が「すべて」のときしか一覧に出ない
- 部署の削除のトランザクションが「子部署 + メンバー + 案件 + 本体」になり、 100 件の上限に近づく
- 移行スクリプトの実行までは、 既存の案件はすべて未所属に見える

### Neutral

- アサイン一覧の期間 (開始日と終了日を入れる方式、 #270) とは UI が違う。 アサインは任意期間の確認、
  案件は一覧の整理と用途が違うため揃えない

## Alternatives considered

- **案件に開始日・終了日を持たせる**: 割り当てと同じ事実を 2 か所に持ち、 食い違う
- **割り当ての最初と最後から案件の期間を作る**: 割り当てに空白がある月にも案件が出る
- **最新の割り当ての日付だけで判定する**: 長期の案件が「今月」に出ない
- **部署の削除で案件を親の部署へ移す**: 受注した部署という事実を書き換える
- **案件がある部署は削除させない**: 組織改編のたびに案件の付け替えを強いる
- **案件に状態 (アーカイブ) を持たせる**: 今回の困りごとは絞り込みで解ける。 必要になったら別の ADR で扱う
- **画面の遷移中にスケルトンを出す (`$app/state` の `navigating`)**: 実装して確かめたところ、 ログイン後の
  画面の遷移ではサーバーへのデータ取得が起きなかった。 ルートの layout の load が `url` を読むのは未ログインの
  分岐だけなので、 SvelteKit は遷移で load を再実行しない (公式: load は参照した `url` のプロパティが変わったときに
  再実行される)。 待ちがないのでスケルトンは出る場面がなく、 見送った
- **最初の表示でストリーミング (load から Promise を返す) を使ってスケルトンを出す**: 待ちが起きるのは最初の表示
  だけで、 SvelteKit 公式の手段はこれになる。 全画面の `data` の受け取り方が変わるため、 別の ADR で扱う

## Implementation notes

- 移行の手順 (本番):
  1. `aws dynamodb create-backup --table-name <table> --backup-name pre-project-department-<date>`
  2. `node scripts/migrate-project-departments.mjs --dry-run` で入れる部署と、 決まらない案件を確認する
  3. `node scripts/migrate-project-departments.mjs` で書き込む。 部署が入っている案件は上書きしない
  4. 決まらなかった案件は案件一覧の編集画面で部署を入れる
